= The Rules card

The Rules card lists the rules Komet has loaded. It is where you decide on a rule the Komet Assistant proposed, and where you write and edit rules yourself.
Komet's rules fire when something is observed, such as a component being focused, and each rule whose conditions hold offers an action, for example an entry in the component's menu.

The card is about Komet's rules, not a concept, so it does not follow the journal's focus.
Add it from the journal's *+* menu.

== The list

Every rule set is listed, proposals first.
A rule set is a group of rules that were written together.

Komet:: Rule sets that are part of Komet.
Plugin:: Rule sets a plugin brought.
Written in Komet:: Rule sets written while Komet runs, by you or by the assistant. Only these have source the card can show and edit.

A name that begins _Proposed_ is waiting for you to decide.
A name that begins _Not accepted here_ is a rule set the knowledge base keeps that you have not accepted on this computer. It is waiting for you too.
A name that begins _Not in use_ has findings that keep its rules from running.

== The selected rule set

Select a rule set to read it: where it came from, whether it is in use, the names of its rules, its findings, and its Java source when it was written in Komet.
The text is selectable and can be copied like any read-only text in Komet.

A finding is what keeps a rule set out of use: a line the compiler refused, a rule Komet would not take, or what a rule did wrong when it ran.
A finding from the compiler names the line of the source it is about.

== Deciding on a proposed rule

A rule the assistant writes is a proposal.
Komet compiles it so that you can see whether it is sound, but none of it runs until you accept it.
Read the source before you accept: a rule is Java that runs inside Komet.

Accept:: Puts the proposed rules in use and keeps the rule set in the knowledge base. If the proposal is an edit of a rule set already in use, it takes that rule set's place.
Discard:: Removes the proposal. A rule set already in use stays as it is.

Accept is not available while a proposal has findings.
Ask the assistant to fix them, and the proposal is replaced with the corrected one.

== Rule sets not accepted here

A knowledge base can contain rule sets that were written somewhere else, for example when you open a knowledge base someone sent you.
A rule is Java that runs inside Komet, so Komet does not run those rules just because the knowledge base contains them.

When Komet starts, it puts a rule set in use only if you saved or accepted that same source on this computer, under your account.
Any other rule set the knowledge base keeps is listed as _Not accepted here_.
Komet compiles it so that you can see whether it is sound, but none of it runs.

Read the source, then choose:

Accept:: Puts its rules in use. From then on Komet puts the rule set in use each time it starts.
Remove:: Takes the rule set out of the knowledge base.

There is no Discard for such a rule set, because the knowledge base would list it again the next time Komet starts.
If the source of a rule set you accepted is changed somewhere else, the rule set waits for your Accept again.

== Writing and editing a rule

New:: On the toolbar. Opens the editor on a new rule set, started from a rule that compiles and offers nothing yet.
Edit:: Opens the editor on the selected rule set, when it was written in Komet. A proposal can be edited too.

In the editor, give the rule set a name and write its Java source.
The name is given once, when the rule set is new: it becomes the name of the rule set in the knowledge base, so no two rule sets have the same name.
A rule is a method of the class, its conditions are methods the rule names, and every rule needs a name no other rule has.
The line and column of the cursor show beside the buttons.

Check:: Compiles the source and lists its findings. Nothing changes.
Save:: Compiles the source and, when it has no findings, keeps the rule set in the knowledge base and puts its rules in use at once. With findings nothing is saved, and the rules in use stay as they are.
Cancel:: Leaves the editor without saving.

Select a finding to select the line it is about.
While the editor is open, the list waits: save or cancel before choosing another rule set.

A rule you save is yours, so it is not proposed and needs no Accept.
When you edit a proposal and save it, your version is put in use and the proposal is removed.

== Removing a rule set

Remove:: Takes a rule set written in Komet out of use, removes it from the list and takes it out of the knowledge base. A rule set that is not accepted here can be removed too.

Rule sets that are part of Komet or of a plugin cannot be removed here.

== What is kept

A rule set you save or accept is kept in the knowledge base, and Komet puts it in use again each time it starts on this computer.
Komet remembers which sources you saved or accepted with your account's preferences on this computer, not in the knowledge base.
The rule set is a concept with the name you gave it.
Each of its rules is a concept too, named by the sentence in the rule's `@Rule`.
The source is kept with the rule set, and each edit you save is a version of it.

What the card writes is an unpublished change, like any other edit in Komet, until you publish it.
A rule set that is not published yet is in use all the same, and it is still there after you quit and start Komet again.

Removing a rule set that was never published takes all of it back out of the knowledge base: its source, and the concepts of the rule set and of its rules.
If the same unpublished change contains other work, such as another rule set that uses one of its rules, only the source is taken back, and the card says that the concepts stay.

Removing a rule set that was published writes an inactive version of its source, which is an unpublished change too.
The concepts of the rule set and its rules stay.

A proposal is not kept.
One you have not decided on is gone when you quit Komet.

Some knowledge bases have no place for rule sets yet.
There the card says so when you save, and the rule set lasts until you quit Komet.

A rule set that no longer compiles, as can happen after Komet is updated, is listed as _Not in use_ with the compiler's findings.
Edit it to fix them.

== The toolbar

Refresh:: Reads the rule sets again. The card shows a proposal as soon as the assistant makes it; use Refresh after rules change some other way.

== Asking the assistant

The Komet Assistant can list the rules, read the source of a rule written in Komet, and run the rules on a component to say what they offer.
It can propose a rule, and it cannot accept one.
See xref:komet-assistant.adoc[The Komet Assistant card].
